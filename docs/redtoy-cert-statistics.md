# 인증 성공 건수

종합통계의 접속수와 회원가입수 사이에 인증건수를 표시하고 조회 기간 합계를 제공한다. 현재 연결된 KCP V2의 main/register/find/pay 공통 결과 처리에서 서버 결과 조회 성공, 복호화 성공, 필수정보 검증 후 기록한다. PC/모바일은 같은 PHP 처리 경로다. 인증 후 가입 중복 또는 계정 찾기 결과로 후속 업무가 거절돼도 본인확인 자체는 성공했으므로 포함한다. 성인 여부나 가입 완료 인원수가 아닌 인증 거래 건수다.

회원/비회원 및 같은 사람의 새로운 인증은 각각 집계한다. 기존 인증 쿠키/세션 복원, 실패/취소, 잘못된 거래키, 결과 조회/복호화 실패는 집계하지 않는다. reg_cert_key의 공급자 구분 포함 SHA-256 해시를 PK로 저장해 같은 거래 재전송은 최초 성공 시각을 유지하며 1건이다. 원본 거래키, 이름, 연락처, 회원번호, CI/DI, IP는 저장하지 않는다. 기존 인증 제한용 cert_history에 추가 기록하지 않아 기존 횟수 제한 정책에 영향을 주지 않는다.

KCP V2 이외 구형 KCB/KCP/LG/이니시스 인증 모듈의 기존 이력을 성공 건수로 합산하지 않는다. 인증 공급자를 변경하면 새 성공 처리 경로도 연결해야 한다. 과거 V2 성공은 기록되지 않았으므로 소급 복원하지 않는다. 화면에 적용 이후 집계임을 안내한다. 데이터가 없는 날은 0, 테이블 미적용/조회 오류는 '-'와 경고로 구분한다. 기록 실패는 개인정보 없는 고정 오류만 남기고 인증을 계속하므로 장애 중 누락된 건은 복원할 수 없다.

## 파일과 영향

- www/adm/shop_admin/redtoy_statistics.php: 열/합계/집계 안내/조회 실패 안내. 기존 500130 읽기 권한과 기간 제한 유지.
- www/adm/shop_admin/redtoy_statistics.lib.php: 기간별 인증 집계 결합. 가입/접속/결제/취소 계산 유지.
- www/lib/redtoy_cert_statistics.lib.php: 준비된 쿼리, 중복 방지 기록 및 날짜 범위 집계. 한국시간으로 저장.
- www/plugin/kcpcert_v2/kcpcert_result.php: 기존 검증 뒤 성공 기록 호출만 추가. 인증 결과·성인 세션·쿠키·리다이렉트 변경 없음.
- tests/redtoy_cert_statistics.php: 격리된 합성 DB 및 API 대체 응답 검증.
- docs/redtoy-cert-statistics-migration.sql.example: 별도 DB 추가.

코어 공통 라이브러리/로그인/결제/주문 처리 변경 없음. 전용 통계 화면과 커스텀 KCP V2 결과 파일만 연결한다. 신규 웹 진입점이나 변경 요청이 없으며 인증 결과는 기존 세션 거래키 검증과 서버 결과 확인 이후에만 기록한다.

## 운영 적용 및 복구

운영 DB에 직접 실행하지 않는다. 실제 G5_TABLE_PREFIX를 확인한다. 운영 배포 브랜치는 이전 확인 기준 codex/rollback-pg-keep-selected이며 코드 공급 브랜치와 구분한다.

1. 변경하는 기존 PHP 3개를 비공개 폴더에 백업한다. 신규 라이브러리와 설정 테이블이 이미 존재하면 중단하고 기존 내용/데이터를 확인·백업한다.
2. migration.sql.example의 신규 InnoDB 테이블을 별도로 생성한다. event_key PK, succeeded_at 날짜 인덱스만 추가한다. 기존 대용량 테이블의 ALTER나 데이터 업데이트는 없다. 기존 데이터 덤프 복원이 필요한 변경이 아니다.
3. SHOW INDEX와 SHOW FULL COLUMNS로 PK/날짜 인덱스/컬럼을 확인한다. 기존 테이블이 있으면 승인된 비공개 DB 백업 절차로 먼저 덤프하고 덮어쓰지 않는다.
4. 신규 라이브러리를 먼저 배치한 뒤 기존 PHP 3개를 반영한다. PHP 문법 검사, Apache 설정 검사 후 재로드한다. DB가 없더라도 인증은 계속되나 집계는 누락되므로 DB를 먼저 준비한다.
5. 통계 화면에서 인증건수 위치, 기간 합계, 빈 날짜, 기존 지표를 확인한다. 운영 인증 API를 자동 테스트하지 않는다. 정상 운영 인증 후 날짜별 증가를 확인한다.
6. 복구는 기존 PHP 3개 원복 후 신규 라이브러리를 제거한다. 기록 테이블은 보존한다. 완전 제거 시 데이터를 비공개 덤프한 뒤 별도 승인하에 DROP TABLE 실제접두사_redtoy_cert_success를 수행한다. 주문/회원 DB를 덮어쓰지 않는다.

인증 성공 시 작은 테이블에 PK 기반 INSERT 1회, 통계 조회 시 날짜 인덱스 범위 GROUP BY 1회가 추가된다. 일반 쇼핑몰 요청에는 추가 쿼리가 없다. 통계 실패 시 원인 상세/거래키를 로그에 출력하지 않는다. DB 연결 자체의 장애/잠금 지연까지 무지연을 보장하지 않는다.

## 검증

REDTOY_COMPLETION_TEST_SOCKET으로 허용된 /private/tmp 격리 MariaDB 소켓만 연결하며 운영 설정을 읽지 않는다. KCP 결과 처리 PHP의 외부 전송만 합성 응답으로 대체해 실패/성공/재전송, PC·모바일 main/register/find/pay, 세션 초기화, 가입 중복 거절, 기록 테이블 누락 시 인증 계속, 날짜 경계/합계/화면 열 위치를 검증한다. 실제 운영 API 호출과 운영 브라우저 테스트는 수행하지 않는다.
