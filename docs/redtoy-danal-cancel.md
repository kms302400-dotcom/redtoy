# 다날 관리자 전체·상품별 취소 및 포인트·쿠폰 정산

## 상태와 범위

운영 적용 전 개발 결과이다. 작업 기준은 기능 브랜치의 `33ccad2`이며 `/private/tmp/redtoy-completion-deploy`의 격리된 작업 트리에서 작업했다. 원래 main 작업 트리의 기존 수정은 보존했다. 마지막 확인된 운영 브랜치는 `codex/rollback-pg-keep-selected`, 운영 HEAD는 `1e0ffbe`이다. 운영에는 기존 기능 패치가 별도로 적용되어 있으므로 main이나 Git HEAD만으로 실제 파일 내용을 판단하지 않는다. 이번 변경을 커밋·푸시·운영 반영하지 않았다.

지원 범위:

- 다날 카드 `card`/`신용카드` 전체취소 및 상품별 부분취소.
- 다날 휴대폰 `hpp`/`mobile`/`휴대폰` 남은 상품 전체취소. 매뉴얼에 부분취소 규격이 없어 휴대폰 부분취소는 서버에서도 거절한다.
- 상품은 같은 `it_id`의 기본/추가 옵션 전체를 함께 취소한다. 상품 수량 일부 취소는 지원하지 않는다. 주문 상세에서 수량을 편집해도 새 취소 화면은 저장된 수량 전체를 기준으로 다시 확인한다.
- 카드 매뉴얼의 승인 후 365일 제한을 검사한다. 휴대폰은 보수적으로 결제월이 지난 거래를 거절한다. 실제 가맹점 계약·통신사·카드별 제한은 별도 확인해야 한다.
- 이전 수동 환불/취소/미수 조정이 있거나 현재 금액과 결제 이력이 맞지 않는 주문은 자동 추측하지 않고 정산 확인을 요구한다. 새 기능으로 처리한 연속 부분취소는 지원한다.
- 결제·본인인증 승인, 다른 PG의 취소, 텔레그램 설정 및 일반 리뷰는 바꾸지 않는다. 기존 고객 직접 취소 기능은 유지하되, 새 관리자 취소와 겹치지 않도록 같은 주문/포인트 잠금 및 미확정 기록 검사를 사용한다.

공식 자료: 사용자가 제공한 `DanalCredit_Manual.1.0.30.Part.doc`의 Bill Cancel 규격 및 `Teledit_Manual.2.4.UI.doc`의 거래 취소 규격, PHP 샘플을 대조했다. 카드 `TXTYPE=CANCEL`, `SERVICETYPE=DANALCARD`, `CANCELTYPE=C/P`, `AMOUNT`, 원거래 TID를 사용한다. 이미 부분환불한 뒤 마지막 잔액을 취소할 때도 `P`를 사용한다. 휴대폰은 `BILL_CANCEL`, `OUTPUTOPTION=3`, 원거래 TID를 사용한다.

## 사용자 흐름과 정산 정책

1. 관리자 주문 상세의 기존 취소 버튼에서 선택 상품을 새 확인 화면으로 넘긴다. 관리자 메뉴 쓰기 권한과 CSRF를 서버에서 확인한다. 구 취소·금액 부분취소 엔드포인트 직접 요청으로 다날 환불을 우회하지 못하게 한다.
2. 서버가 주문과 상품·실제 포인트·쿠폰 사용 이력을 조회해 환불액/반환액/회수액을 계산한다. 임의로 POST한 금액은 사용하지 않는다. 상품명 등 HTML 출력은 이스케이프한다.
3. 10분간 유효한 회원/주문/선택상품/견적 해시를 세션에 보관한다. 실제 실행 때 다시 계산하고 달라지면 거절한다. GET 요청이나 미리보기로 PG를 호출하지 않는다.
4. 최종 확인 시 취소 요청을 영구 기록한 후 PG를 호출한다. 카드 성공 코드만 믿지 않고 취소금액·잔액·거래번호 및 응답에 원거래번호가 있으면 일치 여부까지 검사한다. 매뉴얼상 선택 응답 필드라도 금액/잔액/TID가 누락되면 안전하게 확인 필요로 남긴다. 휴대폰은 성공 코드·원거래번호·취소일시를 검사한다.
5. PG 성공이 확인되면 상품 취소·재고 복원·포인트·쿠폰·환불 누계·세금과 판매수량을 반영한다. 기존 취소 통계 기록 함수도 호출한다. 입금액 원본은 보존하고 `od_refund_price`에 환불 누계를 남긴다. 결제 취소에 알림톡/메일 API를 추가 호출하지 않는다.

정산:

- 상품별 기본/옵션 가격에서 상품 쿠폰을 차감하고 주문 쿠폰을 원래 상품 순금액 비율로 배분한다. 사용 포인트는 할인 후 상품금액과 순배송비에 배분한다. 정수 나머지를 일정한 상품행 순서로 나눠 여러 번 취소해도 총합이 어긋나지 않는다.
- 선택 상품에 배분된 현금/사용 포인트만 반환한다. 배송비와 배송비에 배분된 사용 포인트는 마지막 상품 취소 때 반환한다. 남은 상품의 무료배송/쿠폰 최저금액 조건을 취소 시점에 다시 계산하여 고객에게 추가 청구하지 않는다. 원래 주문의 할인 배분을 유지한다.
- 상품/분류 쿠폰은 실제 적용 상품이 모두 취소될 때 그 주문의 사용 로그만 제거한다. 분류쿠폰의 적용 상품이 여러 개로 해석되어 특정할 수 없으면 거절한다. 주문·배송비 쿠폰은 전체취소 때 반환한다. 쿠폰 자체·원래 만료일·최소 사용조건은 바꾸지 않으며, 만료 쿠폰을 되살려 기간을 연장하지 않는다.
- 사용 포인트 반환은 원래 결제 사용 이력과 주문값이 일치할 때만 허용한다. 반환 포인트는 기존 `insert_point` 만료 정책을 따른다. 현재 신규 적립이 비활성화돼 있어도 기존 사용분 정산은 수행하며 DB 설정은 바꾸지 않는다. 반환할 활성 회원 계정이 없으면 PG 호출 전에 수동 정산 확인을 요구한다.
- 배송완료 적립 `@delivery`는 실제 양수 이력만 회수한다. `ct_point_use`만으로 지급됐다고 추정하지 않는다. 과거 결제 적립 `@member/주문번호/상품구입`은 실제 지급액을 원래 상품 순금액 비율로 배분해 취소분만 회수한다. 유효한 취소 대상 적립건의 미사용분부터 소진 처리해 이후 만료 시 다시 차감되는 것을 방지한다. 원본 지급 이력을 삭제하지 않고 별도의 `@redtoy_cancel/주문번호/취소작업번호:recover` 음수 이력을 남긴다. 포인트를 이미 사용했다면 잔액이 음수가 될 수 있다. 이미 만료된 미사용 포인트를 다시 차감하지 않는다. 구형 만료 처리의 사용액과 실제 소비를 구분할 수 없는 만료·사용 혼합 이력은 PG 호출 전에 별도 정산 확인을 요구한다.
- 사용분 반환도 `@redtoy_cancel/주문번호/취소작업번호:return` 관계를 남기고 기록·잔액 일치를 검사한다. 동일 작업 재요청으로 두 번 반환/회수하지 않는다.

## 장애 및 동시 처리

요청은 `requesting → pg_ok → applying → done`으로 진행한다. 통신 단절, 예상과 다른 응답, 거절 응답, PG 성공 후 DB 오류는 `review`로 남긴다. 프로세스가 죽어 `requesting/pg_ok/applying`에 남아도 재요청은 차단한다. 자동으로 PG를 다시 호출하거나 미확정 건을 성공 처리하지 않는다. 카드 취소 거래번호는 내부 오류가 나더라도 지우지 않는다.

기존 자동완료와 동일한 `redtoy_complete_order_주문번호`, `redtoy_save_order_point` 잠금을 사용한다. 관리자 상품 상태/결제내역 변경, 일괄 상태 변경과 고객 직접 취소도 같은 잠금을 따른다. 취소 미확정 기록은 자동완료·자동 적립/재시도·기존 수동 완료 적립에서 제외한다.

적용 테이블이 모두 InnoDB면 PG 호출 이후의 내부 변경을 하나의 DB 트랜잭션으로 처리한다. 기존 테이블 엔진은 자동 변경하지 않는다. MyISAM이 섞인 환경은 다중 테이블 원자성을 보장할 수 없으므로, 중간 실패 시 일부 내부 변경이 남을 수 있다. 이 경우 기록을 review로 고정하고 자동 재실행하지 않는다. 미확정 건을 임의로 done 처리하거나 기록을 지우면 안 된다.

확인 필요 건의 수동 복구 절차:

1. 해당 주문의 추가 상태/금액 수정을 중지한다. 관리자 확인 화면의 작업번호로 journal 상태/금액/원거래번호/취소 거래번호를 조회한다. 원본 스냅샷은 관리자 또는 서버 관리자만 조회하며 공개 URL/로그로 내보내지 않는다.
2. 다날 파트너센터에서 해당 원거래의 취소 거래번호·누적 취소액·잔액을 대조한다. 단순 타임아웃을 실패로 간주하지 않는다.
3. 취소가 안 된 것이 확인되면 상품·재고·포인트·쿠폰·환불액이 스냅샷과 일치하는지 확인한다. 이미 PG 취소됐다면 추가 PG 요청 없이 누락된 내부 정산만 특정한다.
4. 상품 `ct_history`의 작업번호, 포인트 보상 관계, 쿠폰 로그 ID, 주문 변경 이력과 재고 사용표시를 대조한다. MyISAM 중간 실패는 일부 처리됐을 수 있으므로 코드를 통째로 재실행하거나 DB 전체를 복구하지 않는다.
5. 확인 근거와 관리자 승인 아래 해당 건만 별도 복구한다. 자동 복구/기록 해제 버튼은 제공하지 않는다. 복구 방식은 실패 단계에 따라 달라지므로 증거 없이 상태만 바꾸는 SQL은 제공하지 않는다.

## 파일과 영향

신규:

- `www/adm/shop_admin/redtoy_cancel.php`: 선택·미리보기·최종 확인·처리 결과. 주문관리 쓰기 권한과 CSRF 검사.

- `tests/redtoy_danal_cancel.php`: 모의 PG/격리 DB/관리자 요청 테스트.
- `docs/redtoy-danal-cancel-migration.sql.example`: 새 이력 테이블 생성.
- 본 문서.

기존 수정:

- `www/adm/shop_admin/orderform.php` (코어): 취소 요청을 미리보기 화면으로 연결.
- `www/adm/shop_admin/orderformcartupdate.php` (코어): 기존 다날 취소 우회 차단, 주문 잠금.
- `www/adm/shop_admin/orderformreceiptupdate.php` (코어): PG 취소 처리 중 결제내역 변경 방지.
- `www/adm/shop_admin/orderlistupdate.php` (코어): 일괄 상태 변경의 동시 처리 방지.
- `www/adm/shop_admin/orderpartcancelupdate.php` (코어): 구 금액입력 방식 다날 부분취소 우회 차단.
- `www/shop/orderinquirycancel.php` (코어): 고객 직접 취소와 관리자 PG 취소의 동시 처리 방지.
- `www/lib/shop.lib.php` (코어): 수동 완료 적립에서 미확정 취소 제외.

직접 결제·상품 상태를 바꾸는 코어 코드 안에 잠금을 넣어야 하므로 테마/스킨만으로 해결할 수 없다. 코어 업데이트 시 위 작은 연결 부분의 재적용이 필요하다. PC·모바일의 다날 주문 값과 관리자 취소를 처리하며 결제 승인 경로는 변경하지 않는다.

## DB·설정·운영 반영 순서

DB: `G5_TABLE_PREFIX + redtoy_cancel` 한 테이블을 별도 마이그레이션으로 생성한다. 애플리케이션 요청에서 CREATE/ALTER 하지 않는다. 기존 데이터·컬럼·인덱스·엔진을 변경하지 않는다. journal은 작업번호 PK, 주문/상태/시각 인덱스, 처리자 ID, 금액, 내부 스냅샷, PG 결과 코드와 거래번호, 처리시각을 저장한다. 주소·연락처·문의 본문·키는 저장하지 않는다.

1. 운영 최신 파일과 diff를 대조한다. 현재 primary main의 다른 미커밋 변경을 섞지 않는다. 이번 변경 파일과 cron을 복구할 수 있게 보관한다.
2. DB 관리자가 주문·상품·옵션·회원·포인트·쿠폰/사용로그의 일관된 백업을 생성한다. MyISAM은 `--single-transaction`만으로 일관성이 보장되지 않는다. 서비스 영향이 있는 읽기 잠금/백업 시점은 운영자가 선택한다. 덤프/비밀 설정은 웹 루트 밖에 보관하고 복구 가능 여부를 확인한다.
3. 실제 prefix를 확인해 마이그레이션의 `g5_`를 대조하고 새 테이블만 생성한다. `SHOW CREATE TABLE`/`SHOW INDEX`로 InnoDB·PK·인덱스를 검증한다. 새 테이블 생성은 기존 주문 테이블 전체 복사/ALTER를 하지 않지만 메타데이터 잠금은 발생할 수 있다.
4. 테스트 환경에서 취소 전용 인증정보·호출 권한·휴대폰 바이너리 경로를 확인한다. 기존 소스에 하드코딩된 값을 새 코드·문서·Git에 복사하지 않는다. 아래 환경변수를 웹 서버의 해당 사이트에만 안전하게 전달하며, 화면이나 로그에 출력하지 않는다.

   - `REDTOY_PG_CANCEL_ENABLED`: 기본 비활성. 검증/승인 후에만 `1`.
   - `REDTOY_DANAL_CARD_CPID`
   - `REDTOY_DANAL_CARD_KEY`: AES256 키의 64자리 HEX.
   - `REDTOY_DANAL_CARD_IV`: 32자리 HEX.
   - `REDTOY_DANAL_PHONE_ID`
   - `REDTOY_DANAL_PHONE_PASSWORD`
   - `REDTOY_DANAL_PHONE_BINARY`: 서버의 검증된 SClient 절대 경로. PHP 실행 계정의 실행 권한 필요.

   카드 인증서 검증을 끄지 않는다. 휴대폰 바이너리는 쉘을 거치지 않는 인자 배열로 호출하며 디버그 출력을 켜지 않는다. 요청/암호문/응답 전체/키를 로그에 기록하지 않는다. 새 코드는 기존 하드코딩 인증정보가 든 라이브러리를 로드하지 않는다. 키를 채팅에 보낼 필요는 없다.
5. 새 테이블 적용 후 PHP 파일을 배포한다. 새 파일이 빠지면 완료 배치의 include도 실패하므로 한 묶음으로 확인한다. PHP 문법과 파일 권한, 운영 cron의 PHP·include 경로를 검증한다. 기존 cron 스케줄·PG 콜백 URL은 바꾸지 않는다.
6. 취소 활성 플래그를 켜기 전에 관리자 미리보기만 확인한다. 미설정 상태에서는 최종 실행 버튼이 비활성이고 서버도 거절한다. PG 환불액이 0원인 상품도 활성 스위치가 꺼져 있으면 내부 취소를 실행하지 않는다. 권한 없는 계정/잘못된 CSRF/조작된 상품번호/금액은 거절되는지 확인한다.
7. 다날 가맹점 계약에서 카드 부분취소·휴대폰 취소 지원, 테스트 키·거래, 휴대폰 취소 제한과 바이너리 응답을 확인한다. 실제 PG 취소 테스트는 별도 승인 후 진행한다. PG 없이 통과한 모의 테스트가 가맹점의 실제 취소 성공을 보증하지 않는다.
8. 승인 후 활성화하고 제한된 정상 테스트 거래의 전체/부분취소에서 PG 잔액·쇼핑몰 환불액·포인트·쿠폰·재고를 대조한다. 현재 운영 주문을 임의로 취소하여 테스트하지 않는다.

롤백: 먼저 `REDTOY_PG_CANCEL_ENABLED`를 끄고 열린 취소 요청을 확인한다. 진행 중 요청이 없을 때 이번 코드 변경만 역적용한다. 이미 PG에 성공한 환불을 코드 롤백으로 되돌릴 수 없다. journal은 장애 조사와 정산 근거이므로 실제 사용 이후 삭제하지 않는다. 새 테이블이 비어 있고 코드를 완전히 롤백했을 때만 DB 관리자가 별도 승인 아래 테이블 삭제를 고려할 수 있다. 기존 DB 전체 복원으로 이후 주문/포인트를 덮어쓰지 않는다.

## 검증

PHP 8.4 / 격리 MariaDB에서 InnoDB·MyISAM을 모두 검증한다. 가짜 주문·회원·쿠폰과 모의 PG만 사용하며 테스트 종료 시 임시 DB를 제거한다.

```sh
REDTOY_COMPLETION_TEST_SOCKET=/private/tmp/redtoy-completion-db.XXXXXXXX/db.sock \
  /opt/homebrew/opt/php@8.4/bin/php -d short_open_tag=1 \
  -d disable_functions=curl_exec,exec,shell_exec tests/redtoy_danal_cancel.php
```

검증 결과: 취소 기능 144개, 기존 배송완료 123개, 결제 직후 미적립 48개 검사 통과. 모든 변경 PHP 문법 및 Git 공백 검사 통과. `shop.lib.php` 문법 검사에서 기존의 선택 매개변수 순서에 관한 PHP 8.4 Deprecated 알림이 있으며 이번 변경과 무관하다.

테스트 항목: 카드·휴대폰 전체취소, 카드 연속 부분취소와 마지막 잔액, 상품 옵션 묶음/재고, 쿠폰 배분·반환·만료일 유지, 실제 지급/미지급/과거 결제 적립/사용·만료된 적립금, 사용 포인트 이력 검증과 반환, 음수 잔액, 전체 포인트 비활성 설정 보존, 잘못된 상품/중복/외부 주문 ID, 다른 처리자/주문의 작업번호 재사용 차단, 금액 조작, 권한·CSRF·확인 nonce, PG 응답 금액/잔액/TID 검증, 통신 미확정·중복 재시도 차단, PG 성공 후 DB 오류, InnoDB 롤백, 미확정 취소의 자동완료/적립/재시도 제외.

운영 DB 접속, 실제 PG/알림톡 호출, 운영 파일 수정은 수행하지 않았다. 전체 브라우저 디자인/실제 가맹점 통신 smoke test는 운영 반영 전 별도 테스트 환경에서 확인해야 한다.
