# 관리자 무통장 입금 확인 버튼

관리자 주문상세의 `결제/배송내역 수정` 왼쪽에 `입금 확인처리` 버튼을 표시한다.
실제 계좌 입금을 확인한 관리자가 누르는 기능이며 은행 거래내역 자동 조회는 하지 않는다.

## 처리와 제한

- 무통장·주문 상태이고 미수금이 있으며 취소/환불액이 없는 주문만 버튼을 표시한다.
- 별도 POST 폼을 사용한다. 수동 수정 폼의 입력값이나 Enter 제출 동작을 바꾸지 않는다.
- 기존 관리자 주문 쓰기 권한과 CSRF 검사를 통과해야 한다.
- 서버에서 주문과 상품을 다시 조회한다. 모든 상품이 주문 상태이고, 상품 합계/상품 쿠폰 합계 및 미수금이 일치해야 처리한다.
- 상품대금 + 배송비/추가 배송비 - 각 쿠폰 - 사용 포인트가 누적 입금액이다. 일부 입금된 주문도 남은 미수금을 반영해 누적액을 저장한다.
- 입금액, 처리 시점의 한국 시각, 미수금 0, 주문/상품 상태 입금만 저장한다. 배송정보·쿠폰·사용 포인트·재고·적립 포인트는 변경하지 않는다.
- 취소 확인 필요 기록이 있으면 차단한다. 기존 취소 이력 테이블 및 전용 취소 라이브러리가 설치된 현재 기능 버전을 전제로 한다.
- 주문별 기존 공용 잠금과 짧은 주문/상품 테이블 WRITE 잠금을 사용한다. 알림을 보내기 전에 모든 잠금을 해제한다. DB 계정에 LOCK TABLES 권한이 필요하다.
- 입금 완료 상태를 다시 처리하지 않는다. 중복 요청 시 재저장 및 재발송을 하지 않는다.
- 저장 후 기존 입금확인 알림톡 경로와 텔레그램 결제완료 경로를 호출한다. 배송 알림톡·메일·SMS를 강제로 발송하지 않는다.

## 실패와 알림

SQL 오류는 테이블 잠금을 유지한 상태에서 변경한 필드를 복원한다. 복원이 실패하면 개인정보 없이 `redtoy_bank_receipt: manual_reconciliation_required`를 기록하며 수동 확인이 필요하다.
MyISAM에서 프로세스 강제 종료·서버 장애까지 원자적으로 복원할 수는 없다. 상품만 입금으로 바뀐 불일치 주문은 재처리 검증에서 차단하므로 주문/상품을 대조해 수동 정리한다.

알림 예외가 발생해도 이미 저장된 입금은 유지한다. 알림톡 예외는 관리자 안내를 표시한다. 실제 수신 여부와 일반적인 전송 거절은 기존 알림톡 발송내역에서 확인한다. 기존 알림톡 코드의 상점메모는 수신 성공 증명이 아니다. 입금 저장 직후 프로세스가 종료되면 알림이 누락될 수 있으므로 발송내역 확인 후 기존 수동 화면에서 별도로 재발송한다. 알림의 자동 재시도/새 발송 큐는 이번 변경 범위에 포함하지 않는다.

## 변경 파일과 배포

운영 코드 3개:

- `www/adm/shop_admin/orderform.php`: 기존 관리자 코어 화면에 별도 폼과 버튼 추가.
- `www/adm/shop_admin/orderformreceiptupdate.php`: 기존 권한/CSRF 검사 뒤 전용 액션 분기 추가. 기존 수동 저장 경로는 유지.
- `www/lib/redtoy_bank_receipt.lib.php`: 금액 검증, 잠금, 저장과 오류 복원.

테마/스킨에서 관리자 폼과 POST 저장을 함께 확장할 훅이 없어 관리자 코어 2곳에 최소 연결 코드를 추가했다. PC/모바일 쇼핑 결제 파일은 변경하지 않는다. 그누보드 업데이트 시 위 두 코어 연결 부분을 확인해야 한다.

DB 구조 변경, 신규 키, cron 변경은 없다. 운영에는 자동 반영하지 않는다. 코드 리뷰 후 운영 파일 차이와 DB 권한을 확인하고 파일/관련 주문·상품 테이블을 백업한다. 새 라이브러리를 먼저 설치하고 코어 2개를 적용한다. 관리자 권한과 CSRF가 있는 실제 브라우저에서 버튼 노출, 정상 입금, 중복 클릭, 수동 수정 및 알림 발송내역을 확인한다. 운영 고객에게 실제 알림이 발송되므로 대상 주문을 확인한 후 테스트한다.

롤백은 이번 변경의 코어 2개를 역패치하고 새 라이브러리를 제거한다. 이미 저장된 입금/상품 상태는 유지한다. 코드 롤백을 이유로 주문 DB 전체 덤프를 복원하지 않는다.

## 검증

운영과 분리된 로컬 MariaDB의 합성 데이터로 테스트한다. 운영 설정이나 실제 알림 API를 읽거나 호출하지 않는다.

```sh
REDTOY_COMPLETION_TEST_SOCKET=/private/tmp/redtoy-completion-db.XXXXXX/db.sock php tests/redtoy_bank_receipt.php
php -d short_open_tag=1 -l www/adm/shop_admin/orderform.php
php -d short_open_tag=1 -l www/adm/shop_admin/orderformreceiptupdate.php
php -l www/lib/redtoy_bank_receipt.lib.php
php -l tests/redtoy_bank_receipt.php
```

InnoDB/MyISAM의 정상 저장, 부분 입금, 할인·사용 포인트 계산, 중복·잠금 경합, SQL 오류 복원, 권한/CSRF, 조작값 무시, 알림 예외 후 저장 유지와 기존 수동 컨트롤러 경로 및 실제 버튼 조각 렌더링을 검사한다. 수동 경로 테스트의 금액/세금 조회와 알림 전송은 스텁으로 분리한다. 실제 관리자 로그인/외부 알림 수신은 운영 반영 전 로컬 자동 테스트 범위가 아니다.
