# 365일 자동 로그인

## 범위

로그인 페이지의 아이디/비밀번호 폼에서 자동 로그인을 기본 체크한다. 체크한 최고관리자·권한 관리자·일반 회원은 기존 쿠키 방식으로 최대 365일간 자동 복원한다. 체크를 해제하면 정상 로그인은 수행하되 기존 자동 로그인 쿠키를 지운다. DB 구조나 서버·cron 설정 변경은 없다.

수정 대상:

- `www/bbs/login_check.php` (코어): POST 체크값 `1` 또는 기존 폼의 `on`일 때만 쿠키를 365일 저장한다. 체크값 누락·해제·비정상 배열값은 저장하지 않는다.
- `www/common.php` (코어): 최고관리자만 차단하던 조건을 제거하고, 유효한 쿠키 복원 후 세션 ID를 교체하고 기존 관리자 클라이언트 키와 회원 인증 토큰을 생성한다.
- `www/theme/buzinga/skin/member/basic/login.skin.php`
- `www/theme/buzinga/mobile/skin/member/basic/login.skin.php`
- `www/skin/member/basic/login.skin.php`
- `www/mobile/skin/member/basic/login.skin.php`
- `www/19m.php`: 위 다섯 화면의 자동 로그인 입력에 `value="1" checked="checked"`만 추가한다. 성인확인 페이지의 인증 처리·이동 로직은 변경하지 않는다.
- `tests/redtoy_auto_login.py`: 운영 설정·DB 없이 실제 PHP 쿠키/세션 및 관리자 검사 코드를 실행하는 로컬 HTTP 통합 테스트.
- `docs/redtoy-auto-login.md`: 적용·검증·복구 안내.

로그인 쿠키 발급과 공통 부트스트랩의 복원은 스킨/후행 extend 훅만으로 함께 바꿀 수 없어 코어 2곳을 수정한다. 그누보드 업데이트 시 이 두 변경을 재확인한다. 주 테마와 코어 기본 스킨을 함께 수정하여 PC/모바일 및 스킨 누락 시 대체 화면을 맞춘다. 사용하지 않는 basic 테마와 사이드 로그인 위젯의 기본 체크 상태는 변경하지 않는다. 위젯에서 사용자가 체크한 `value=1`은 같은 서버 처리로 지원한다.

## 보존하는 동작

- 관리자 진입 및 메뉴별 읽기/쓰기 권한, CSRF 검사 코드는 변경하지 않는다. 관리자 자동 복원 시에도 기존 클라이언트 검증을 거친다.
- 차단·탈퇴·메일 미인증 계정의 자동 복원 제한을 유지한다.
- 비밀번호가 달라지거나 기존 검증에 포함된 브라우저/서버 정보가 바뀌면 기존 자동 로그인 쿠키가 맞지 않아 복원하지 않는다.
- 로그아웃은 기존처럼 자동 로그인 쿠키와 세션을 해제한다.
- 로그인 성공 시 기존 `ss_cert_adult` 처리, 성인확인 쿠키 복원, 회원의 `mb_adult` 데이터는 그대로 둔다. 자동 복원에 성인인증 통과 값을 새로 추가하지 않는다.
- 주문·PG·알림·포인트 코드는 변경하지 않는다.
- 소셜 제공자 OAuth 연동은 변경하지 않는다. 이번 검증은 아이디/비밀번호 로그인과 해당 자동 로그인 쿠키 복원 기준이다. 소셜 콜백이 체크값을 전달하지 않는 경우 새 자동 로그인 쿠키를 발급하지 않는다.

365일은 발급 시점부터 쿠키의 최대 유효기간이며 매 방문마다 연장하지 않는다. 브라우저 쿠키 삭제·보관 정책·로그아웃·비밀번호/브라우저 정보 변경으로 더 일찍 해제될 수 있다. 기존 쿠키 형식을 유지하므로 배포 전 발급된 유효한 쿠키도 남은 유효기간 동안 사용할 수 있다. 기존 코드는 체크하지 않아도 쿠키를 발급했으므로, 배포 후 자동 로그인 선택을 다시 확인하려면 한 번 로그아웃한 뒤 로그인한다.

## 검증

```sh
REDTOY_TEST_PHP=/path/to/php python3 tests/redtoy_auto_login.py
```

Python 표준 라이브러리와 기존 PHP만 사용한다. 테스트용 임시 폴더에 로컬 세션과 합성 계정을 만들고 127.0.0.1에 잠깐 PHP 서버를 실행한 후 종료·삭제한다. 실제 `login_check.php`, 자동 복원 구간, 쿠키·세션 함수, 관리자 진입/클라이언트 키/메뉴 권한/CSRF 함수를 실행한다. DB 조회와 메일 발송은 합성 스텁이며 운영 DB·외부 API·실제 메일은 사용하지 않는다. 로컬 HTTP에서 HTTPS 판정을 모사하여 Secure·HttpOnly 응답 속성을 확인한다.

검사 항목: 관리자/회원 정상 로그인 및 브라우저 종료 후 복원, 정확한 365일 만료, 체크 해제와 잘못된 체크값, 기존 `on` 값, 로그아웃, 비밀번호/브라우저 변경·쿠키 변조, 차단/탈퇴/메일 미인증 회원, 일반회원 관리자 접근 제한, 권한관리자 읽기/쓰기 제한·권한 회수, 관리자 세션 키 변조, CSRF 성공·실패·재사용, 기존 성인인증 세션 보존과 복원 시 허위 인증값 미생성, 다섯 화면의 기본 체크 속성.

수정 PHP 7개에 `php -d short_open_tag=1 -l`을 실행한다. 모바일 테마 원본의 CRLF 줄바꿈을 보존했으므로 공백 검사는 `git -c core.whitespace=cr-at-eol diff --check`를 사용한다. 일반 `git diff --check`의 해당 줄 CR 경고는 기존 줄바꿈 형식이며 줄 전체 정규화는 하지 않는다.

## 운영 적용과 복구

운영에는 자동 반영하지 않는다. 현재 기능 브랜치 기반 변경이며 실제 운영 저장소의 브랜치를 확인하고 변경 파일의 적용 충돌 검사와 백업을 먼저 한다. DB 마이그레이션·인증키·cron 변경은 필요 없다. PHP 문법 검사 후 Apache 재로드로 OPcache를 갱신하고 로그인 화면의 기본 체크, 체크 해제, 관리자/일반회원 브라우저 재시작 후 복원, 로그아웃, 성인확인 화면과 관리자 권한을 확인한다. 운영의 실제 로그인·본인인증·OAuth는 로컬 테스트에서 호출하지 않았다.

복구는 이번 변경의 웹 파일 7개만 역패치하거나 보존한 원본을 복원하고 Apache를 재로드한다. DB/주문/회원 데이터를 복원할 필요는 없다. 발급된 쿠키는 로그아웃으로 해제한다. 최고관리자 자동 복원이 다시 차단되더라도 아이디/비밀번호 직접 로그인은 유지된다.
